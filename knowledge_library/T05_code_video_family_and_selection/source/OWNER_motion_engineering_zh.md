# Motion Engineering（一人 Bot 動畫工作室）

日期：2026-10-22 入庫
來源：Felix 2026-10-22 分享的 X 貼文，Mori（@0xjmori）於 2026-10-18 發表的 X Article《Motion Engineering: One Bot, Five Departments, an Entire Studio》
證據等級：實務者方法論長文（作者為 2,229 追蹤的小帳號；文中無實測數字、無公開 repo）。技術棧本身（Claude Code、Remotion、FFmpeg、Remotion 官方 Agent Skills）皆為真實既有工具；「用 Opus 5.5 跑完整支片」的成果屬作者自述，未獨立驗證。

## 一句話概念

不讓模型直接生成影片像素，而是讓一個 coding agent 按「工作室分工」寫動畫程式碼、渲染、自我檢查、局部修訂，把產品動畫片做成可重複運轉的生產系統。

## 技術棧

- Agent：Claude Code（文中指定模型 Claude Opus 5.5，此為作者文中說法）
- 影片框架：Remotion（React 元件，畫面是 frame 編號的函數，逐幀渲染）
- 媒體處理：FFmpeg（抽參考片幀、量測時間、檢查輸出、處理素材）
- 工作區檔案：CLAUDE.md（工作室常規）、BRIEF.md（本片 brief）、STYLE.md（視覺方向）、STORYBOARD.md（分鏡與事件），原始碼與已核准素材跟 review 產物分開存放，工作室靠檔案接續，不靠單一對話

## 核心方法：五個部門，一個 Agent

同一 agent 依序扮演五個角色，重點是責任分離，各有專屬指示、檔案與驗收標準：

1. **Director**：動工前寫 brief，決定觀眾每段要理解什麼（核心是 before/after 關係）。紀律：先核對產品真的有要演示的功能、截圖真的展示了它；缺關鍵畫面要開口要，不准畫一個逼真的假畫面。
2. **Art Director**：給 2 到 3 個參考，各自指派用途（一個定字體、一個定轉場、一個定節奏），萃取設計原則而非抄畫面。用 FFmpeg 從參考片抽幀、量測轉場時間，寫進 STYLE.md。風格指南同時定義「要避免什麼」。
3. **Animator**：先有 shot list 再寫碼。連續性原則：一場的結束狀態就是下一場的開始狀態。時間轉成幀號（30fps 下 20 秒 = 600 幀），事件落在精確幀位（游標 180 幀到按鈕、195 幀點擊、210 幀結果出現），改時間就是改幀號，不重生整支。
4. **Render Engineer**：渲染與設計分開。先渲代表性靜幀（四張關鍵幀先講完故事），再渲互動區間的短預覽；判斷對象是渲染產物，不是原始碼的意圖。
5. **Critic**：不准 Animator 自己核准自己。用新 context，只帶 brief 與渲染出的幀來評；發現綁幀號回報（附 RECHECK 幀清單），靜幀查版面、動態預覽查節奏與轉場，兩者不能互相替代。

## 修訂迴圈與停止規則

- 局部修復：210 幀的缺陷只修那裡，保留已核准的部分；不准為了讓 review 過關而拿掉驗證要求。
- 有迭代上限與升級路徑：超過限度就說明阻塞點、請人給方向。
- 交付不是一個檔案：多畫幅要各自做版面（直式不是橫式裁切），各自渲靜幀與 review；交付包 = 成片、海報幀、可編輯原始檔、已核准素材、殘留限制說明。

## 複利機制（文章的真正主張）

- 工作室留下、專案換掉：風格規則、元件、檢查清單、渲染指令跨專案保留；重複出現的錯誤要變成規則、元件或新檢查項，而不是每次手動修。
- 第一個專案跑通後，把流程結晶成 Claude Code Skill（只放方法，不放該專案的產品名、截圖、文案）。
- 對「一鏡到底的爆紅影片」的拆解：作者引 Claude Code 團隊 Thariq 的說法，那支 prompt 通常內含完整 brief、參考、shot list、技術限制與驗收規則，而且 agent 繼承了既有的專案、設計系統與渲染管線。能複製的是環境，不是咒語。

## 限制與邊界（作者自承＋查證註記）

- 適用：產品發表動畫、介面演示、字體影片、數據視覺化、短解說，這些能用程式精確表達的片種。
- 不適用：寫實場景、複雜角色、有機的電影感運動，仍需實拍、3D 或生成式影片。
- 主觀品質不能完全化約成檢查項；音樂與音效的權利、客戶期待、發布決定仍是人的事。
- 全文無量化證據（成本、耗時、成功率皆未給數字），方法可信度來自流程設計的合理性與工具的真實性，不是實測結果。

## 在技術地景中的位置（僅定位，不涉應用）

與本庫的 HyperFrames、huashu-motion 同屬「影片即程式碼」家族。差異：技術棧是 Remotion/React（另兩者是 HTML/GSAP 或 HTML/CSS）；著力點不在渲染或單一 skill，而在組織設計：部門分工、人核准關卡、Critic 獨立評審、錯誤結晶成規則、流程結晶成 Skill。
